Chepicky 메인 서비스 — v5 (관리자 도구와 동일한 디자인 언어 / MVP 수동 입력)

■ 이번 버전에서 바뀐 것

1. 디자인 통일
   - 관리자 도구와 같은 결로 정리했습니다. 밝은 배경(#FAFAFA) + 흰 카드 + 1px 라인,
     체리색(#C41E3A)은 강조에만, 숫자는 모노스페이스로 통일.
   - 다크 테마를 걷어내고 라이트 단일 테마로 고정했습니다.

2. 로그인 화면
   - 배경이 체리색이 아니라 앱 본문과 같은 밝은 배경입니다. 로고가 체리색입니다.
   - 카카오/네이버 버튼을 빼고 '간편 로그인' 버튼 하나로 정리했습니다.
   - 화면 세로 중앙 정렬로 재구성해 스크롤 없이 한 화면에 들어옵니다.

3. 스크롤 제거
   - 로그인 / 카드 선택 / 실적 입력 / 고정비 화면은 100dvh 안에 고정됩니다.
     목록이 길어질 때만 목록 영역 내부에서 스크롤되고, 하단 버튼은 항상 보입니다.
   - iPhone 390x844 기준으로 실제 렌더링해 스크롤이 생기지 않는 것을 확인했습니다.

4. 버튼
   - 그라데이션을 전부 제거하고 단색(체리색)으로 통일했습니다.
   - 비활성 상태는 회색 단색, 눌림은 살짝 축소되는 정도로만 반응합니다.

5. 카드 선택
   - 카드사 칩 → 카드 목록 구조. 아직 지원하지 않는 카드는 "혜택 정보 준비 중"으로 흐리게.
   - 하단에 "찾는 카드가 없나요? 설정 › 카드 요청에서 알려주시면 혜택 정보를 먼저
     준비할게요." 안내를 넣었고, 설정 탭에 실제 요청 입력란을 만들었습니다.
   - 다른 카드사에서 고른 카드도 하단에 칩으로 계속 보여, 뭘 골랐는지 놓치지 않습니다.

6. 금액 입력 (신규)
   - 모든 금액 칸이 입력하는 즉시 쉼표를 찍습니다. (32000 → 32,000)
   - 칸 아래에 한글 금액이 같이 뜹니다. (32,000 → "3만 2천원")
     0을 하나 더 치거나 빠뜨린 걸 눈으로 바로 잡을 수 있습니다.
   - 추천 금액, 실적 입력, 고정비 금액 모두 같은 방식입니다.

7. 피킹률을 첫 화면에
   - 추천 탭 최상단에 이번 달 피킹률을 크게 배치했습니다. 옆에 돌려받은 돈과
     기록 건수가 함께 나옵니다. 서비스의 핵심 지표라 가장 먼저 보이게 했습니다.

8. 가시성
   - 본문/보조 텍스트 색을 전반적으로 진하게 조정했습니다.
     (보조 텍스트 #6E6E76 → #4E4E58, 흐린 텍스트 #9A9AA2 → #71717C)
   - 입력칸 글자를 16px 굵게, 테두리를 진하게 바꿔 값이 또렷하게 보입니다.
   - 라벨을 11px → 12px로 키우고 색을 올렸습니다.

9. MVP 수동 입력 — 최소화
   - 최초 1회만 입력합니다. 카드당 숫자 2개뿐입니다.
   - 지난달 실적은 금액을 적는 대신 '구간'만 고릅니다.
     [30만원 미만] [30~50만원] [50~100만원] [100만원 이상] 중 탭 한 번.
     정확한 숫자를 몰라도 되고, 카드사 앱에서 대충 보고 고를 수 있습니다.
   - 기간을 날짜로 못박아 어떤 금액인지 헷갈리지 않게 했습니다.
     · "07/01~07/31 이용 금액"
     · "당월 1일~08/27 이용 금액"  (오늘 날짜가 자동으로 들어갑니다)
   - "어디서 보나요?"를 회색 박스 + ▼ 화살표로 바꿔 눌러서 펼치는 것임을
     분명히 했습니다. (이전엔 그냥 글씨라 아래 문장과 헷갈렸습니다)
   - "이 카드는 300,000원부터 혜택이 켜져요"는 지웠습니다. 구간 버튼에 이미
     같은 정보가 있어 중복이었습니다.
   - 하단에 "이 앱을 이번 달 1일부터 쓴 게 아니라면 당월 금액이 실제와 조금
     다를 수 있다"는 안내와, 결제 내역을 채울수록 정확해진다는 점을 넣었습니다.
   - 전월 실적 조건이 없는 카드는 아예 입력을 요구하지 않습니다.
   - 이후에는 결제 기록이 쌓이면 그것으로 자동 계산되고, 입력값은 설정에서 고칠 수 있습니다.
   - 건너뛰기도 가능합니다.

10. 고정비 저장 + 카드 비교
   - 통신비 / 쿠팡 와우 / 네이버플러스 / 넷플릭스 / 유튜브 프리미엄 / 디즈니+ /
     스포티파이 / 보험료를 프리셋으로 준비했습니다. 눌러서 추가하고 금액과 결제 카드만
     고르면 됩니다.
   - 저장한 고정비는 매달 이번 달 사용액과 실적, 한도 소진에 자동으로 반영됩니다.
     매달 다시 입력할 필요가 없습니다.
   - 결제 카드를 고를 때 카드마다 이 고정비에서 받게 될 혜택 금액이 함께 보입니다.
     (예: 통신비 55,000원 → 신한 +5,500원 / 삼성 +825원 / 토스 혜택 없음)
   - 지금 고른 카드보다 나은 카드가 있으면 아래에 알려줍니다.
     "'신한카드 처음'으로 결제 변경하시는 걸 추천드려요! 매달 4,675원 더 받습니다."
     받침에 따라 '으로/로'가 자동으로 바뀝니다.
   - 온보딩 3단계와 설정 탭 양쪽에서 관리할 수 있습니다.

11. 이용처 검색
   - 이용처가 8개를 넘을 때만 검색칸이 나타납니다. 평소엔 칩만 있어 단순합니다.
   - 가게 이름으로 찾을 수 있습니다. "스타벅스" → 카페, "배민" → 배달앱,
     "넷플릭스" → OTT/구독.

12. 메인 화면 — 내 카드 기준으로 연동
   - 이용처 칩은 "내가 등록한 카드가 실제로 혜택을 주는 이용처"만 나옵니다.
     카드를 바꾸면 목록도 따라 바뀝니다.
   - 추천 결과는 1위 카드를 크게, 나머지는 한 줄씩 압축해 한 화면에 담았습니다.
   - 추천 전에는 카드별 실적 진행률(다음 구간까지 얼마 남았는지)이 보입니다.
   - "이번 달" 탭에서 사용액·피킹률·카드별 남은 한도·결제 기록을 확인합니다.

■ v5.1 수정사항

1. 고정비가 피킹률에 반영됩니다
   - 원인: 혜택 금액을 '결제를 기록하는 순간' 계산해서 저장하는 구조였는데,
     고정비는 사용자가 기록하는 게 아니라 자동 생성되는 항목이라 혜택이 0으로
     남아 있었습니다. 그래서 쓴 돈에는 더해지고 혜택에는 안 잡혀 피킹률이 깎였습니다.
   - 수정: 혜택을 저장하지 않고 매번 다시 계산하는 방식으로 바꿨습니다.
     이번 달 결제를 날짜순으로 정렬해 한도를 순서대로 소진시키며 계산합니다.
     고정비도 일반 결제와 똑같이 혜택이 잡히고, 내역을 고치면 전체가 즉시 다시 맞춰집니다.
   - 고정비에 결제일(1~28일)을 등록할 수 있습니다. 등록한 날짜에 결제된 것으로
     계산되므로 일 한도가 있는 카드에서도 정확합니다.

2. 결제 내역 직접 추가 · 수정
   - '이번 달' 탭에 [+ 직접 추가] 버튼이 생겼습니다. 날짜·금액·카드·이용처를 넣습니다.
   - 기록을 누르면 같은 폼이 열려 수정하거나 삭제할 수 있습니다.
   - 고정비 항목은 목록에 '고정비'로 표시되며, 수정은 설정 탭에서 합니다.
     (매달 반복되는 항목이라 한 달치만 고치면 혼란스럽기 때문)

3. 선택한 이용처가 항상 보입니다
   - '어디에 결제하나요?' 오른쪽에 현재 고른 이용처가 배지로 붙어 있습니다.
     칩 목록을 옆으로 밀어도 무엇을 골랐는지 사라지지 않습니다.
   - 추가로 선택한 칩이 화면 밖에 있으면 자동으로 가운데로 끌어옵니다.

■ v5.3 추가 기능

1. 신규 발급 유예 실적
   카드사는 새로 발급한 회원에게 실적이 없어도 첫 구간 혜택을 주는 경우가 많습니다.
    · 신한 처음      : 등록월+1개월까지 30~50만원 구간 혜택
    · 삼성 iD SELECT : 발급월+1개월까지 40~80만원 구간 혜택
    · KB NEED Pay    : 다음달 말일까지 40~80만원 구간 한도의 50%
    · Hi-Point Plan+ : 등록월+1개월까지 50~100만원 구간 혜택
   온보딩과 설정에서 "이 카드, 최근에 새로 발급받으셨나요?"를 물어보고,
   해당하면 실적이 모자라도 첫 구간 혜택이 켜집니다.
   KB처럼 한도가 절반인 카드를 위해 capRatio(한도 비율)까지 반영합니다.
   백엔드에서 온 카드는 유의사항에 "등록월+1개월", "발급월+1개월" 같은 표현이
   있으면 자동으로 유예 카드로 인식합니다.

2. '이번 달' 탭 카드별 필터
   결제 기록 위에 [전체] [카드A] [카드B] 칩이 생깁니다. 카드별 건수도 함께 표시됩니다.
   카드가 2장 이상일 때만 나타납니다.

3. '카드별 남은 한도' -> '카드별 혜택 한도' 로 문구 변경

4. 카드 교체 제안 (신규)
   이번 달 결제 기록을 등록된 모든 카드로 다시 계산해 더 나은 카드를 찾아줍니다.
   "현재 사용중인 'A카드'를 'B카드'로 대체하시면 월 6,403원을 더 받아요"

   금액은 단순 혜택 차이가 아니라 연회비까지 반영한 순이득입니다.
     월 순이득 = (바꿨을 때 혜택 - 지금 혜택) - (새 카드 연회비 - 지금 연회비) / 12

   [어떻게 계산했나요?]를 펼치면 계산 근거가 모두 나옵니다.
    · 옮겨서 계산한 결제 건수와 금액
    · 지금 카드 혜택 / 바꿨을 때 혜택 / 연회비 차이(월) / 월 순이득
    · 연회비를 12로 나눠 월 단위로 환산했다는 설명
    · 소비 패턴 유지를 가정한 값이며, 새 카드는 실적을 처음부터 채워야 한다는 주의

   혜택이 줄어도 연회비를 더 아끼면 순이득이 날 수 있고, 그 경우도 잡아냅니다.
   카드당 결제 기록이 4건 이상 쌓여야 분석하며, 바꿔서 이득인 카드가 없으면
   "지금 카드 조합이 가장 좋아요"라고 알려줍니다.

■ 할부 처리 (v5.2)

결제 방식을 일시불 / 할부 / 무이자할부 중에서 고를 수 있습니다.
추천받을 때와 결제 기록을 직접 입력·수정할 때 모두 선택합니다.

무이자 할부는 두 가지가 동시에 적용됩니다.
 1) 혜택 제외 — 어느 카드로 결제해도 할인·적립이 0원입니다.
 2) 실적 제외 — 전월 이용금액 산정에서 빠집니다.

근거는 각 상품설명서입니다.
 · 신한카드 처음   : "무이자할부(슬림할부 등 부분 무이자 포함) 이용거래" 적립 제외
 · 삼성 iD SELECT  : "무이자할부 이용금액" 할인 제외
 · KB NEED Pay     : "무이자할부 이용금액" 제외

2번이 특히 중요합니다. 예를 들어 한 달에 일시불 40만 + 유이자 할부 30만 +
무이자 할부 60만원을 썼다면 총 130만원이지만 실적으로 인정되는 건 70만원입니다.
무이자 할부를 실적에 넣어 계산하면 100만원 구간으로 잘못 판정되어, 다음 달
혜택을 실제보다 크게 안내하게 됩니다. 이 부분이 반영되어 있습니다.

유이자 할부는 혜택도 받고 실적에도 들어갑니다(일시불과 동일하게 계산).

무이자 할부를 고르고 추천을 누르면 순위를 매기는 대신, 혜택이 없다는 사실과
일시불로 바꾸면 어떻게 되는지를 안내합니다. 그 상태로도 기록은 남길 수 있습니다.

카드별로 규칙이 다르면 카드 데이터에 noFreeInstallmentBenefit: false 를 주면
그 카드만 무이자 할부에도 혜택을 계산합니다. 기본값은 '혜택 없음'입니다.

■ 백엔드(카드 혜택 DB) 연동

관리자 도구가 저장한 카드를 이 앱이 읽어옵니다.

  관리자 도구(로컬) --저장--> Cloudflare Worker + D1 <--읽기-- 메인 서비스(GitHub Pages)

연결 방법은 두 가지입니다.

  (a) 코드에 박아두기: index.html 상단의
        const BACKEND_URL = "";
      에 Worker 주소를 넣고 다시 배포합니다. 접속하는 모두에게 적용됩니다.

  (b) 앱에서 입력하기: 설정 탭 > 카드 혜택 데이터 에 주소를 넣고 [다시 불러오기].
      그 기기에만 저장됩니다. 재배포 없이 바로 테스트할 때 편합니다.

주소가 비어 있으면 앱에 내장된 데모 카드 3장으로 동작합니다.

동작 방식
 - 앱을 열면 /api/public/cards 를 호출합니다. 공개여부가 '공개'인 카드만 내려옵니다.
   관리자 도구에서 '초안'이나 '검수완료'로 저장한 카드는 앱에 보이지 않습니다.
 - 받아온 목록은 기기에 캐시됩니다. 다음에 열 때 네트워크가 안 되면 캐시를 씁니다.
 - 카드 선택 화면의 카드사 탭과 카드 목록이 이 데이터로 자동 구성됩니다.
 - 관리자 스키마와 앱 카드 모델이 달라서 중간에 변환기(adaptCard)가 있습니다.
   · 실적구간[].최소금액        -> tiers
   · 월최대적립가능혜택_구간별  -> overallCaps
   · 혜택[].서비스명            -> groups (구간별 한도, 일 한도 포함)
   · 혜택[].건당최대혜택 ÷ 비율 -> 1회 인정 이용금액(perTxnCap)
 - 이용처(카테고리) 목록은 사용자가 고른 카드에 따라 자동으로 달라집니다.
   내 카드가 실제로 혜택을 주는 이용처만 칩으로 나옵니다.
   예) 신한카드 처음만 = 12개 / 토스 삼성카드만 = 6개 / 둘 다 = 13개
   카드를 바꾸면 목록도 바뀌고, 고른 이용처가 사라지면 첫 항목으로 돌아갑니다.
 - 앱에 미리 적어둔 24개 목록에 없는 이용처가 백엔드에서 와도 버리지 않고
   목록 뒤에 붙입니다. 관리자 도구에서 새 이용처(예: '반려동물')를 쓰더라도
   앱 코드를 고칠 필요가 없습니다.
   단, 앱이 아는 이용처는 가게 이름 검색(스타벅스 -> 카페)이 되고 순서가 정해져
   있는 반면, 처음 보는 이용처는 이름으로만 검색되고 맨 뒤에 붙습니다.
   자주 쓰게 되면 index.html 의 CATEGORY_GROUPS 와 CATEGORY_KEYWORDS 에 추가하세요.

■ 실행

정적 파일이라 그대로 HTTPS 호스팅에 올리면 됩니다.
iPhone Safari에서 접속 → 공유 → 홈 화면에 추가.

■ 데이터

카드 선택, 실적 입력값, 고정비, 결제 기록 모두 이 기기의 localStorage에만 저장되며
서버로 전송하지 않습니다. (키 접두사: chepicky:)
